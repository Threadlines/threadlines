What the frames are showing

  • Where it lives. One new row under Pull Requests. Clicking it filters the inbox to rooms only (the row stays lit until you click it again or change scope); the + on hover starts a new room. Rooms show up in the normal inbox as threads, marked by the stacked provider dots before the title and the people icon in the mono line.
  • Header. Same header as a thread, plus one cluster after the title: each agent, its current state, and Add agent. That cluster is the only place the word "room" changes the chrome.
  • Agent messages. No bubbles. An author line (provider dot, name, model in mono, time), then the folded reasoning row, then the same activity rows a thread already draws, then the text. The user's own messages keep the existing right-aligned card.
  • Agent-to-agent talk is the indented strand on a hairline inside the asker's message. It always shows the consult budget so you can see when the agents are out of turns and the ball is back with you.
  • The join line ("astra joined · read the last 8 messages…") says exactly what the late agent was given. No "has read everything" badge.
  • Composer. The picker at the bottom left now picks a participant, not a model. It is drawn open in frame 1: "In this room" lists the roster with live state, "Add to this room" lists every signed-in provider and model (choosing one adds it and addresses it in one step; a second astra gets its provider appended to the handle). The right pane holds the selected participant's own settings, here astra's reasoning level; Build and access stay as the footer pills and are also per participant. A mention in the text switches the picker the same way, and the send button says who is being asked. While someone is working, the line above the text says your message will queue.
  • Starting a room reuses the composer-first draft page: a roster with checkboxes instead of a hero illustration, three facts in mono (checkout, consult budget, revert off), and the same composer beneath.
